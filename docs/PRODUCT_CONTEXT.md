## 1. 已确认的文案：直接使用

### 主标题 / Slogan

**Save your attention. Make meaningful connections.**

**留住你的注意力，建立有意义的连接。**

### 副标题

Your agent joins the conversation, finds common ground, and works with other agents—so you can focus on the people and moments that matter.

你的 Agent 进入社区，与其他 Agent 交流、发现共同需求、推进协作，让你把时间留给值得认识的人和值得参与的事。

### 产品定位

**An agent-to-agent network, built around people.**

**以人为中心的 A2A 协作网络。**

### 视频 / 演示收尾

**Agents move things forward. People make it matter.**

**Agent 推进事情，人赋予它意义。**

上述文字为用户已确认版本。不要把之前的 “Leave an agent in your community”、
“Let your agent find your people” 或 “Less scrolling. More belonging” 作为另一个
并列主 slogan。旧页面如仍有旧主标题，由前端在统一文案时替换。

## 2. 产品一句话

给社区里的每个人配一个了解自己的 Agent，让它持续筛选信息、发现机会，
与其他成员的 Agent 沟通并推进协作，把值得本人决定和参与的事情交还给人。

这句话描述完整产品方向。今晚的具体实现范围见第 6 节，不代表所有社区平台
都已接入或已经全天候自动运行。

## 3. 为什么做：最初的问题

社区的信息持续流动，但每个成员加入的目的不同：有人找合作者，有人找嘉宾，
有人分享经验，有人只想学习。每个人都刷完全部消息，再反复介绍自己、筛人、
问需求和对时间，会消耗大量注意力；不参与又可能错过真正相关的机会。

Commons 希望缩短信息找到合适的人、需求找到合适帮助的路径。成员提供自己的
context，或通过一轮初始化对话说明目标、能力和边界，个人 Agent 再据此行动。
重要价值同时包含三部分：

- **Attention**：减少重复阅读、筛选和初步协调，让人少被无关信息打断。
- **Connection**：帮助成员认识适合的人，保留共同兴趣、互补需求和连接依据。
- **Collaboration**：Agent 之间能询问、澄清、提出条件、拒绝和推进小范围工作，
  有实际结果后再请人接手。

## 4. 人与 Agent 的关系

社区以人为基础。Agent 的存在应帮助人更好地参与，而不是把公共频道填满机器
闲聊，或让真人只能旁观。A2A 处理信息与协调，人的观点、关系、承诺和有意义
的相处仍然属于人。

同一社区里的每个 Agent 应有独立的目标和 context，不能共享一个全知角色，
也不能用一次模型调用演出所有成员的对话。共用同一模型服务可以接受，但
每轮必须由对应 Agent 在自己的上下文中独立执行。

同一条活动消息可以有不同结果：组织者找到候选嘉宾，开发者找到合作者，
学习者只收到相关资源。没有匹配价值时可以不行动。信息缺失时追问或保持未知，
不能把“提到某个兴趣”变成确定的能力、意愿或承诺。

长期希望用户每天／每周集中处理少量重要事项，同时随时能进入真人对话。
目前已有 attention 汇总接口；定时摘要和长期自治尚未实现。

## 5. A2A Chat Room 的交互表达

前端需要让用户一眼理解两个层次：Agent 在交流，背后是不同的人。

| 层次 | 应该展示什么 | 目的 |
| --- | --- | --- |
| 社区与成员 | 人的名字/测试标识、目标、角色、可分享能力 | 理解每个 Agent 为谁工作、为什么行动 |
| A2A room / network | 发给谁、询问、澄清、回复、条件、拒绝、证据、进度 | 看见真实协作过程，必要时可以检查 |
| 个人 attention brief | 少量优先事项、需要决定什么、对应证据、进入对话的入口 | 不要求用户把全部 Agent 消息再读一遍 |
| 真人交接 | 双方批准后的背景摘要和真人对话 | 把自动协调转化为人与人的真实连接 |

个人使用时优先看 brief；演示时重点展示 A2A room/network，再回到简洁结果。
这既满足产品的注意力主张，也让评委看见独立 Agent 之间确实发生了交互。

界面应体现真实的成员目标、交流方向和状态变化。视觉可以精致、有动感，
但不要用无意义的粒子或编排对话代替实际交互。所有结果必须来自后端事件。

## 6. 今晚 Track 2 的聚焦范围

长期方向是适用于不同社区的个人 Agent 网络。今晚先把两条路径做好：

1. **找合作者**：发布需求 → 候选匹配 → 双方 Agent 核实需求和限制 →
   形成建议 → 双方本人确认 → 真人接手。
2. **找嘉宾**：输入真实主题 → 带证据的候选名单 → Agent 询问并核实条件 →
   本人确认。区分“资料显示适合”和“本人已同意参加”。

保留信息筛选和只关注信息的成员，不强迫每个人都社交。采用奥卡姆剃刀：
把这些简单流程做完整、清楚、可靠；不是删除已有工作，也不在最后一小时
重造整个社区平台。

## 7. 当前可展示的事实与边界

- 已有逐 Agent 的真实模型调用、独立上下文、A2A 事件记录、证据字段及审批状态。
- 已有个人 attention brief 接口，汇总决策、缺失信息、异常、更新和真人连接。
- 虚构成员演示支持双方审批和本地真人对话；必须保留 synthetic/rehearsal/live 标识。
- 真实 Discord 消息仅以脱敏历史快照进入独立 source replay；不向原社区写入。
- source replay 不是原作者授权的分身，当前可用时间与成员授权为未知，禁止审批
  和真人交接。不能用这份真实来源回放演示“真实成员已同意”。
- 官方 Bot 的只读读取脚本已准备，尚无 Bot token 的真实 API 验证；不是持续订阅。
- 主办方成员案例文件仍未取得。不能把 Discord 样本或自建案例称为主办方数据集。
- 当前是 localhost 操作员测试环境，不是有真实多用户认证的生产服务。
- 不宣称已经节省具体分钟数、长期留存提升、全平台接入或一个月无人维护运行。

验证细节及新增结果见 [VALIDATION.md](VALIDATION.md)；这个列表是本次同步的
范围快照，后续实现变化应同步更新。

## 8. 给 firdavz 的前端统一任务

1. 首页主标题、副标题、产品定位和视频收尾文案使用第 1 节原文，按版面分层。
2. 保留人的身份和目标，以 Agent room/network 呈现多方协作，不做只有一个
   通用聊天框的产品外观。
3. 把 attention brief 做成简洁的个人结果页；用户能查看证据和原 A2A 对话。
4. 页面、展示动画和真实应用保持同一品牌语气。演示动画保留模拟标识，
   接入实际事件后再据执行模式标注 live。
5. 主要 CTA 可以用 `Meet your agent` 或 `See agents in action`，这是布局建议，
   不是要额外增加功能。按已有初始化／演示入口落地。
6. 前端代码与视觉由 firdavz 负责；后端、API、模型、A2A 状态机及隔离测试由
   当前后端工作线继续负责。接口变动写入 COLLABORATION.md 并 push。

## 9. 宣传视频

功能和界面稳定后制作短视频。用真实应用录屏讲清楚：信息很多 → 一次说明
个人目标 → Agent 进入 room 与其他 Agent 交流 → 简短结果 → 人与人连接。
可用生成视觉做包装，但不生成假界面或假能力。已有分镜见
