# Commons Spider — 原版 dashboard 方案

这是与另一条前端工作线分开的方案。独占写入范围：`public/spider/`、
`scripts/spider-preview.mjs`、两个 spider 测试文件、本说明及专属截图。
没有修改另一条方案的 app/page.tsx、app/ui、全局样式或品牌资源。

## 打开

先让现有 Commons 后端在 3402 运行，然后：

```sh
node scripts/spider-preview.mjs
```

打开 http://127.0.0.1:3403/ 。独立预览服务只绑定 loopback，并把同源
`/api` 请求转到 3402；不另开模型配置或 Discord 权限。

主页面是用户要求的**原版蜘蛛 dashboard 复刻适配**：左侧长群聊文本、
机械蜘蛛、密集蛛网、逐词抓取与飞行、右侧四路分类、底部图表、时间轴、
速度/循环/放大/沉浸和原版控制抽屉。

此前的布局保留在 http://127.0.0.1:3403/workspace.html ，用于完整成员设置、
attention 收件箱、真实演示发起、双向测试审批、续问和本地真人对话。

## 四路分类

| 输出 | 规则及含义 |
| --- | --- |
| people / 人物 | 已知成员名或输入消息的发言者提及，可查看成员 context |
| signals / 信息 | 需求、提供帮助、可用时间、限制等词语线索 |
| keywords / 关键词 | 与成员技能和社区词表匹配的主题 |
| events / 活动 | 活动、日期、时间等提及，不等于已确认活动 |

支持粘贴自己的聊天文本，最多 12,000 字符、280 条提取线索。自动快照包含
成员上下文、最近三个需求和最近十二条真实模型交流，均标注各自来源类型。
这是一份组合上下文，不能称为完整原始 Discord 消息流。

**文本分类是本地可解释规则，不是 LLM 语义抽取。** 扫描动画回放实际提取结果；
不会沿用原版的 175 次分流、195 个词或模拟概率，不会自动发起外部交流。
重复人名按提及次数计数。点击词条可追溯到具体输入消息。

## 底部图表

1. 最近真实 A2A 模型调用耗时：来自后端 call.durationMs。
2. 提取结果点阵：一颗彩点对应一条实际提取线索。
3. 人物/话题球形分布：实际去重标签叠在装饰球面上；不声称是已验证关系图。
4. 个人注意事项：已查看会话、待决策事项和无需处理的结果，来自 attention API。

右侧控制台可运行真实 A2A；运行结束后可将新的实际交流记录载入蜘蛛扫描。
模型调用次数与文本扫描次数分开，源消息回放依旧禁止代替真实成员审批。
